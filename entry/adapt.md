# 入口：adapt — 把已有的东西改造成标准 deck

适用于：一份分析报告、一个数据网页、一份旧 PPT、别的工具导出的 HTML 幻灯片、一段带可视化的回放。

**给人**：

> 按 deckflow 的流程，入口是 adapt。
> 原稿：（路径或链接）
> 这次给谁讲、讲多久：……
> 原稿里我最想保留的：……
> 原稿里可以不要的：……

---

**给 AI**：

改造不是换皮。原稿通常是为**阅读**写的，deck 是为**讲**做的，两者的结构不一样。

### 1. 盘点原稿

```
python tools/new.py <name>
```

把原稿登记为 `sources.md` 里的来源，然后列一张清单：

| 原稿里的东西 | 类型 | 去向 |
|---|---|---|
| 每一张图、每一张表、每一个结论、每一段可视化 | 图 / 数据 / 论点 / 交互 | 保留 / 重画 / 合并 / 不要 |

"去向"一列是你的提案，由人确认。

### 2. 从原稿反推 brief

听众、时长、语言从人的话里取；风格口径（标题风格、页面上放什么）如果原稿有明显倾向，写进 brief 并标明是推断。

**→ G0**

### 3. 重新做分镜，不是照搬章节

原稿的章节顺序往往是"背景—方法—结果—讨论"。为讲而做的顺序通常是"问题—最关键的一张图—它为什么成立—代价—所以呢"。

每页的 `point` 用你自己的话重写，`source` 指回原稿的具体位置（"S1 图 3""S1 第 4 节的表"）。

**→ G1**

### 4. 搭建时的三种处理

- **原稿的图**：忠实重画成 deck 的风格——同样的数据、同样的坐标、同样的结论，换成统一的配色、足够大的字号、完整的坐标轴标注。不要顺手换一种图表类型；想换，回分镜提。
- **原稿内嵌的数据**：直接取出来用（内联的 CSV / JSON 是最好的来源），标 `data-src`。只有图片没有数据时，可以从图上读数，但必须标 `data-derived`，并向人要原始数据。
- **原稿的交互或动画**：取它的**数据**，用 deck 的组件重做（`Kit.player`、`Kit.panzoom`），而不是用 iframe 把原页面嵌进来——iframe 在托管环境里会变成空白，风格也对不上。

### 5. 自检，交付

同 [new](new.md) 的第 5 步。另外在 `review.md` 里附上第 1 步的清单最终版，让人能看到原稿的每样东西去了哪里。
