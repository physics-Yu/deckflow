# 入口：new — 从主题和材料开始

**给人**：把下面这段连同你的主题和材料一起交给 AI。

> 按 deckflow 的流程做一份新的汇报，入口是 new。
> 主题：……
> 听众和时长：……
> 材料：（文件路径、链接、之前的对话、仓库……）
> 我已经想清楚的：……
> 我还没想清楚的：……

"还没想清楚的"和"想清楚的"一样有用：它告诉 AI 哪里该提案，哪里该照做。

---

**给 AI**：按顺序做，每个闸门停下来等人。

### 1. 读材料，建 deck 文件夹

```
python tools/new.py <name>
```

把人给的每一份材料都真的读一遍。读不到的记下来，不要跳过。

### 2. 起草 `brief.md` 和 `sources.md`

brief 里能从上下文推断的先填上，不确定的列成问题。**最多问三个问题**，只问那些答案会改变你怎么做的：

- 汇报的落点是什么？（比如：是给出我们的结论，还是向听众提问？）
- 时长和形式？
- 有没有一份你认可的旧 deck 可以对齐风格？

sources 里每份材料写清楚它对什么内容有最终解释权。发现材料之间数字对不上，现在就提出来。

**→ G0：等人确认 brief。**

### 3. 起草 `storyboard.md`

先用一句话写出整份汇报的主线。写不出来，说明还没到做分镜的时候，回去和人讨论。

然后每页一个条目。检查每一条：

- `point` 是一句话吗？是这页独有的吗？
- 删掉这页，主线会断吗？不会就删。
- `visual` 是一张具体的图吗（类型、坐标轴、要标出什么）？
- `source` 指向 sources.md 里的编号吗？缺的写"缺"。

把你自己拿不准的结构选择写在 `comment` 里（"这两页可以合并，理由是……"）。

**→ G1：等人逐条批准。** 第一版分镜被大改是正常的，这正是它便宜的地方。

### 4. 搭建

只做 `approved` 的页。从 `templates/deck/deck.html` 开始。

- 先把全部页面的骨架和主图位置搭出来，再逐页做细。
- 等材料的位置放 `.placeholder`，结构和视觉先调好，材料到了再填。
- 需要核实的引用先标 `data-unverified`，攒到一起统一检索、逐条对回原文。

### 5. 自检，交付

按 [docs/workflow.md](../docs/workflow.md) 的 S4 做完三件事，在 `review.md` 开第一轮记录，然后告诉人：

- deck 在哪、多少页
- 还缺哪些材料（点名）
- 哪些是你自己加的或推断的

之后进入 [revise](revise.md)。
