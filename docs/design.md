# 设计原则与发挥空间

契约管"能不能看"，这一份管"好不好看、讲没讲清楚"。这里的每一条都是判断，不是检查项；AI 应该理解理由，然后自己拿主意。

## 一页一件事，一件事一张图

- 先问这页要让人带走什么（分镜里的 `point`），再问哪张图能让这件事**一眼看出来**。图是论据，不是装饰。
- 文字只做三件事：标题、图上的标注、一句读图提示。解释留给讲的人。
- 一张图说不清，优先拆页，其次分步出现，最后才是加文字。
- 数据多不等于信息多。问每一条曲线、每一个数字："删掉它，这页的结论会变弱吗？"不会就删。

## 图要画到位

- **能画就画**：电路、几何、流程、示意图都应该用 SVG 画出来，不要留"此处应有图"，也不要用一段文字描述一张图。
- **忠实于原图**：人给了图，就照着重画、美化，不要另起炉灶换一种表达；想换，先在分镜里提。
- **坐标轴写全**：写含义和单位，用听众熟悉的显式记号（写 I/I₀，不写自己起的单字母代号 s）。
- **图上直接标结论**：安全区、危险区、最优点、阈值线，直接画在图上，不要让人对着图例找。
- **放大要有出处**：局部放大用框选 + 引线接到子图，让人知道放大的是哪一块。
- **示意图要标明是示意图**：`data-kind="schematic"`。真实数据到了再换。

## 交互是为了讲清楚

每个控件都要回答"它让听众多看到了什么"。

- 值得做：拖一个参数看排名交换；点一个对象看它怎么传播；动画回放一个过程；切换两种方案做对比。
- 不值得做：只是把一张图换成另一张的标签页；没人会调的滑块；调了也看不出变化的旋钮。
- 动画配三样东西：播放速度（要有真正慢的档位）、带阶段标记的进度条、滚轮缩放和拖动。`Kit.player` 和 `Kit.panzoom` 提供这些。
- 整份 deck 是一条连贯的叙事时，让前一页的对象在后一页继续出现，而不是每页重新开始。

## 版面

- 字号下限是底线不是目标。图上的文字宁大勿小，24px 起。
- 留白是版面的一部分；图下面空一大块时把图放大，或垂直居中。
- 页面上不放不提供信息的东西：页脚署名、章节标签、装饰性的小提示。要放什么由 brief 决定。
- 少用表格。能配图的配图，能做成卡片的做成卡片，表格留给真正需要逐格对照的内容。
- 颜色有含义就保持含义：同一个对象在整份 deck 里用同一种颜色。

## 诚实

- 每个数字能追到来源。追不到的，要么标出来让人确认，要么不放。
- 结论的强度和证据对齐："同构于一个已被证明困难的问题"和"已被证明困难"是两句话。
- 模型的假设写在图注里（一行，不是一段）。

## 发挥空间

契约之外的一切都是开放的。具体来说，参与者（人或 AI）可以在这些地方自由发挥，不需要改动内核：

| 层面 | 可以做什么 | 放在哪 |
|---|---|---|
| 叙事 | 结构、顺序、从哪切入、用什么类比 | `storyboard.md` |
| 图 | 任何 SVG / Canvas；自己写的可视化；嵌入的回放 | `deck.html` |
| 交互 | 任何 JavaScript。`Kit` 只是省事，不是限制 | `deck.html` |
| 主题 | 配色、字体、字号比例 | `themes/*.css` |
| 版式 | 不用 `.cols` `.card` 这些辅助类，自己写 grid | `deck.html` 的 `<style>` |
| 规则 | 在 brief 里改默认值；在页面上豁免 | `brief.md`、`data-allow` |

想把一种做得好的图沉淀下来给别人用，加到 [recipes.md](recipes.md)；想改硬规则，提 issue 讨论，因为它会影响所有 deck。
